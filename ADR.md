# Architecture Decision Record — GeoMech-LogML v0.1

**Status:** accepted · **Date:** 2026-09-03 · **Scope:** research prototype, single-repo Python system

One page, one table per decision: context → decision → rejected alternatives → consequence.

| # | Decision | Context | Choice & rationale | Alternatives rejected | Consequence |
|---|----------|---------|--------------------|-----------------------|-------------|
| 1 | **Package layout** | Must ship a library + app + tests + notebooks reproducibly. | Single installable package `geomech_logml` with domain sub-packages (`data`, `preprocessing`, `models`, `uncertainty`, `interpretability`, `app`, `pipeline.py`) + top-level `tests/`, `notebooks/`, `scripts/`. Config module (`config.py`) is the single source of truth for column names — every layer reads it. | Flat script; monorepo with separate services. | Import name uses underscore (`pip install -e .`); zero drift between app/CLI/library column names. |
| 2 | **Physics-based synthetic generator first** | Development/testing needs paired log↔static data we can't get (proprietary core data). | Built the Agbada forward model *first*: Markov facies → overpressured Athy compaction → log response (Archie, Han velocities) → ground-truth statics. Known truth enables honest end-to-end validation; every published-range constraint is testable. | Pure random-noise toy data; public datasets (Volve etc. — wrong setting, no static core set, licensing). | All 39 tests + demo run without proprietary data; real LAS/CSV drops into the identical schema. |
| 3 | **Inputs: legacy triple-combo (+ optional Vp)** | Hard constraint: no mandatory shear/dipole sonic. | Feature whitelist enforced in `features.py`; Vp-dependent features (`VP`, `PHIS`, `AI`) auto-drop when absent. Vs exists *only inside* the generator to create truth, never as input. | Requiring sonic; using Vs-derived quantities. | The app degrades gracefully to the `eng_no_vp` set; ablation quantifies Vp's marginal value. |
| 4 | **Learn the static↔dynamic conversion inside the model** | Literature often applies a fixed E_dyn→E_stat factor post-hoc — unphysical and untestable. | Models regress static properties directly from logs; the mismatch becomes an implicit, input-dependent function the model learns from paired (core) rows. No conversion factor exists anywhere in the codebase (test-enforced by construction). | Hard-coded ratio; two-stage dynamic→static regression. | Predictions are made in one step; the learned behaviour is visible via SHAP (porosity/clay dominate). |
| 5 | **Strictly well-wise CV** | Random row splits leak via depth autocorrelation and inflate scores. | `WellKFold` / `LeaveOneWellOut` group whole wells; all metrics are pooled out-of-fold (blind-well). Even sklearn MLP's internal early-stopping (a *random* split) is disabled. | Random K-fold; depth-block CV within one well (still leaks well idiosyncrasy). | Honest metrics (~0.83–0.97 R² here); strictness is why inter-well bias shows up honestly in interval coverage. |
| 6 | **Model portfolio: RF + XGBoost + shallow MLP** | Requirement to compare three families on tabular petrophysics. | Per-target estimators (not multi-output): SHAP, QRF leaves and hyper-parameters stay per-property honest; RF=XGBoost=strong baselines, MLP=nonlinear benchmark. Modest fixed hyper-parameters (no random-split tuning). | One multi-output model; deep learning (data-hungry, unjustified at core-plug scale); stacking ensembles. | Slightly more fits; simpler interpretability; CPU-only training in ~1 min. |
| 7 | **Uncertainty: QRF + well-wise split conformal** | Need finite-sample intervals; spatial data breaks exchangeability. | Dual method: (a) QRF (Meinshausen 2006) exact leaf-quantiles — row-adaptive width; (b) split conformal with **calibration wells held out inside each fold** — absorbs inter-well bias. Coverage validated on truly blind wells and reported, warts and all. | Gaussian error assumption; quantile XGBoost only; random-split conformal. | QRF under-covers when wells shift systematically (documented) — conformal is the primary calibrated band; both shown side-by-side. |
| 8 | **SHAP everywhere** | Engineers must trust and audit every prediction. | `ShapExplainer`: TreeSHAP for RF/XGB (exact), KernelSHAP over k-means background for MLP. Summary + dependence + per-depth waterfall in app, notebook and CLI artifacts. | LIME/coefficients/one global importance. | Waterfall needs scalar base value handling (done); MLP explanation is slower (progress shown, subsampled). |
| 9 | **Streamlit for the UI** | Non-programmer petroleum engineers; Python-only stack; no build toolchain. | Single-file dashboard + helper modules (`plots.py`, `report.py`), six tabs, session-state caching, `AppTest`-verified flows, CSV/markdown export. Tested via `streamlit.testing` in CI. | Flask/FastAPI+React (two toolchains); Dash (heavier); Gradio (poor multi-tab fit). | UI logic is testable Python; heavy compute cached (`cache_resource`); widget-state guards keep untrained state render-safe. |
| 10 | **Reproducibility discipline** | Research prototypes rot without pins. | Global seed constant threaded into every RNG/estimator; deterministic generator (test-enforced); `requirements.txt` + `pyproject.toml`; Dockerfile with import smoke-test + healthcheck; example dataset committed. | Ad-hoc seeds; unpinned `latest` deps. | Bit-identical reruns for a given seed; container rebuilds are self-verifying. |
| 11 | **CLI + library + app share one pipeline** | Same experiment from three doorways (app, notebook, terminal). | `pipeline.run_experiment` is the single orchestrator; `scripts/train_eval.py` and the app both call it; reports generated from the same builder. | Duplicate logic per surface. | Metrics/methods cannot diverge between UI and CLI outputs. |

**Key trade-off accepted:** honest well-wise validation + honest interval reporting *cost* some headline accuracy vs. leaked random-split scores seen in parts of the literature — that is deliberate and is the project's core methodological stance.
